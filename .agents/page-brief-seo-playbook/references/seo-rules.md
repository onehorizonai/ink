# SEO Rules

Use these rules to make a page brief search-aware without letting SEO take over the page's job.

## Decision Order

Work in this order:

1. confirm whether organic search matters
2. define one primary intent
3. check overlap with existing pages
4. lock metadata, headings, links, structured data, and supporting-content modules around that intent

## Start With Intent

- Decide whether the page is meant to rank organically.
- If organic search is not a meaningful goal, state that clearly and keep SEO guidance light.
- Prefer one primary intent per page:
  - informational
  - commercial investigation
  - transactional
  - navigational

## Product-Led SEO

- Build around real product, user, or problem territory.
- Avoid chasing adjacent traffic the business cannot credibly serve.
- Connect search intent to a business outcome, not just pageviews.

## One Page, One Core Target

- One page owns one main intent or topic cluster.
- Check existing pages before recommending a new target.
- If another page already targets the same intent, recommend updating or differentiating instead of creating overlap.

## Metadata Contract

- Write one exact title tag for the final brief.
- Write one exact meta description for the final brief.
- Write one exact slug for the final brief.
- Do not pass metadata options into the final brief.

## Internal Linking

- Link pages according to role:
  - product and feature pages -> pricing, demo, related features, docs
  - solution pages -> related solutions, customer proof, product capabilities
  - comparison pages -> pricing, migration, feature detail
  - help pages -> adjacent docs, support, billing or account paths
  - evergreen resources -> related guides and product pages
- Avoid orphan pages.

## On-Page Structure

- Keep one H1-level promise.
- Use descriptive section headings.
- Match length to intent and topic depth, not a word-count superstition.
- Prefer answer-first structure for help, Q&A, and snippet-seeking sections when that format is justified.
- Use tables for honest comparisons and structured data-heavy explanations.
- Use ordered lists for sequences and unordered lists for option sets when they genuinely help.

## Keyword Use

- Use primary and supporting terms naturally.
- Put the key topic in the exact title, H1, opening context, and relevant section headings when it fits.
- Do not repeat exact phrases mechanically.
- Do not use keyword density as a target.

## Supporting Content And Snippet Opportunities

- Do not force a FAQ onto a page.
- Choose the support module that best helps the user complete the page goal.
- Valid support modules include FAQ, docs CTA, comparison table, setup steps, related integration links, proof block, pricing note, security note, or `none`.
- Use FAQ only when the current page already has one, search intent clearly calls for Q&A, or the user asks for it.
- When FAQ is selected, keep questions tightly related to the page and use real user phrasing.
- When docs or setup support is more useful, use exact docs links or setup steps instead of FAQ.

## Overlap Triage

- If an existing page already owns the intent, recommend updating it.
- If two pages must coexist, define the difference in audience, job, or funnel stage explicitly.
- If that difference cannot be stated clearly, treat the new page as overlap risk.

## Page-Type-Specific SEO Notes

- Comparison pages often benefit from tables and objection handling.
- Help pages benefit from clear question phrasing and direct answers.
- Evergreen resource pages benefit from cluster logic and internal linking.
- Integration pages often need platform-specific terminology and links to docs or setup.
- Landing pages may have little organic intent; do not force an SEO article structure onto them.

## Things to Avoid

- fake keyword metrics
- fake SERP claims
- padding sections to hit an arbitrary length
- stuffing exact-match phrases into every heading
- creating multiple pages for the same intent without a clear differentiation
