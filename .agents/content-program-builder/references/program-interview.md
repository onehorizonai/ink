# Program Interview

Ask only for details that cannot be discovered from the repo, the selected profile, One Horizon context, or the existing corpus.

## Minimum Needed

- Program name or working title.
- Primary goal.
- Target audience.
- Channel or channels, using `channel-taxonomy.md` when possible.
- Repeatable format.
- Route or automation boundary for each format.
- Cadence or batching preference.
- What Ink should automate.
- What remains manual.
- Whether the new pack should be `local/private` or `public/tracked` as part of the open-source repo. Ask this directly before creating files.

## Useful Optional Details

- Example posts or references.
- Brand assets or design constraints.
- Tone boundaries.
- Approval flow.
- Scheduler or publishing tool used manually.
- KPIs the user actually tracks.
- Campaign dates.
- Hard compliance, rights, or claim constraints.

## Defaults

- Storage: no default for new programs. Ask `local/private` vs `public/tracked` before creating files. For existing programs, preserve the current storage visibility unless the user asks to move it.
- Status: `draft` for user-created programs, `starter` for tracked generic examples.
- Calendar: create the standard header and one placeholder row only when helpful.
- Performance: create the standard header and no invented metrics.
- One Horizon: use `[Ink Program] <name>` under `Ink - Programs` when tracking is requested and tools are available.

## Do Not Ask

- Which profile to use if the prompt, `INK_PROFILE`, or single-profile config resolves it.
- Which specialized route to use when the program can infer it from the channel and format.
- For performance data before the program has published runs.
